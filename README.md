# 讲义笔记 LectureNotes

把课堂录音变成**能直接复习的笔记**：手机录的音导进来 → 自动转成文字 → 自动切分主题、挑出重点 → 生成带时间轴的 Markdown 笔记。

一条录音从导入到成稿，全程在你自己的电脑上完成，不需要 Python、不需要 ffmpeg、不需要 Docker，也不需要注册任何账号。

---

## 一、先说调研结论：为什么最后是自己写

你要求先看开源界有没有更成熟的方案。我把 GitHub 上相关的项目都过了一遍，结论如下：

| 开源项目 | 是什么 | 为什么没有直接拿来用 |
| --- | --- | --- |
| [Hyprnote](https://github.com/fastrepl/hyprnote) | 本地优先的「会议 AI 记事本」，本机录音 + Whisper 转写 + LLM 总结，最接近需求 | 它是**桌面应用**而不是网站；偏会议场景；**手机录音导入 → 课堂笔记格式**这条链路要自己接；Windows 支持也还在完善 |
| [Whishper](https://github.com/pluja/whishper) | 自托管网页版转写/字幕工具，带 Web UI，纯本地跑 Whisper | 转写很强，但**不做**「课堂重点提取 + 笔记格式」；需要 Docker 整套部署 |
| [Whisper-WebUI](https://github.com/jhj1017/Whisper-WebUI) | Gradio 网页界面，功能全（批量、字幕、翻译） | 需要 Python + ffmpeg 环境；同样不产出复习笔记 |
| [Open Notebook](https://github.com/lfnovo/open-notebook) | NotebookLM 的开源替代，做资料研究笔记 | 面向文档研究，不处理课堂录音流水线 |
| [whisper-web](https://github.com/xenova/whisper-web)（Xenova） | 浏览器里跑 Whisper 的示范项目 | 只是个 Demo，没有笔记、没有存储、没有长音频处理 —— **但它的技术栈（transformers.js）我直接复用了** |
| ScribeCat / Noted / VoiceVault / scrybe 等 | 个人练习性质的小项目 | 成熟度不够，代码量小、维护少，不如自己写可控 |

**结论：**
- 语音识别这一层，**没有理由自己造轮子** —— 直接复用成熟的 Whisper 生态：浏览器端用 [🤗 Transformers.js](https://github.com/huggingface/transformers.js)（ONNX Runtime + WebGPU/WASM），云端可选硅基流动 SenseVoice / OpenAI / 任何 OpenAI 兼容接口（包括你自己搭的 faster-whisper、Whishper）。
- 「手机录音导入 → 自动分主题 → 挑重点 → 生成笔记格式」这一层，**没有现成且好用的开源方案**，所以自己写了薄薄一层。
- 你这台机器上**没有 Python、没有 Node、没有 ffmpeg、没有 Docker**（我都查过了），所以整个东西被设计成**零外部依赖**：服务端只用 Node 内置模块（现在约 2700 行），前端是纯静态页面（约 3500 行 JS + 740 行 CSS），转写在浏览器里跑。双击就能用。

## 二、能做什么

- **导入**：手机录音（m4a / mp3 / wav / amr / webm…）、电脑文件拖拽、或直接用电脑麦克风录音
- **转写**：浏览器本地 Whisper（免费、离线、不上传）或云端 API（快、准、适合长录音）
- **转写后自检**：自动清洗 —— 繁转简、半角标点转全角、删乱码符号/emoji；再用大模型按上下文纠正音近错字
- **自动整理**：转写一完成，笔记就自动生成好了（主题分段、重点句、关键词、概念定义、老师强调、考点、作业安排、自测题），不用再点第二次
- **思维导图**：树形发散图（根 → 主题 → 知识点），线条是量完节点位置后现画的贝塞尔曲线，不是拿 CSS 拼的直角肘。**叶子节点是一句压缩过的知识点、不是关键词**（`椭圆方程x²/16 + y²/9=1` 而不是「椭圆方程」），前面带一个类型小标签（公式 / 定义 / 定理 / 结论 / 步骤 / 例题 / 易错），主题后面有个圆圈数字表示这节抽出几条；时间徽标点一下就跳到老师说这段的位置。规则判不出类型的句子宁可不挂 —— 口语化很重的离线转写录音里，这一节会是空的，比挂半句胡话强。宽屏是横着的树，手机上会自动竖过来（横树在 390px 上必然要左右滑，时间徽标正好滑出视野）
- **公式能看**：笔记和逐字稿里的 LaTeX（`\( \frac{d^2y}{dx^2} \)` 这类）直接渲染成分数、上下标、根号、∑∫、π/α/θ，导出 Word 时也转成可读的纯文本，不会出现一堆反斜杠
- **带时间轴的笔记**：笔记里每个 `12:34` 都能点，音频直接跳到老师说这句话的位置
- **导出**：Word（.docx）、**PDF**（字体已嵌入，手机上打开、发群里、打印都不会乱版）、Markdown、纯文本逐字稿、SRT 字幕 —— 五种。笔记类导出只带正文：不含那份给网页端折叠用的逐字稿附录（要原文就导 txt / srt），也不含「需要回听核对的地方」那一节（那是给自己看的，导出是给人复习的）
- **三种笔记风格**：应试重点版 / 提纲版 / 康奈尔版 —— **每条录音各自选**：新建时弹窗里问（导入文件或录完保存前），之后在左侧录音列表每一行最右边那个「⋯」上改（鼠标移上去会变成「编辑」）
- **每门课各写各的**：同一条录音还能单独填提示词（法学课「法条编号写全」、高数课「推导别跳步」），两门课互不干扰
- **重点条数自适应**：默认按主题长短自动定（2~8 条），也可以手动指定 3 / 5 / 6 / 8 / 10 条 —— 离线笔记和 AI 润色都照这个来
- **可选 AI 润色**：接上任意 OpenAI 兼容大模型（硅基流动、OpenAI，或自定义 DeepSeek/通义/Kimi/Ollama…），把自动生成的口语笔记再润色成书面复习资料
- **双栏可收**：笔记和逐字稿并排看，逐字稿那栏右上角有「收起 ›」，收起后笔记吃满整行（嫌一行太长就再点「展开逐字稿」回来），偏好会记住。收起是为了看更宽的东西 —— 笔记卡铺满内容区，跟上面的标题、播放器、工具栏左右对齐
- **详情页是「应用外壳」不是长文档**：打开一条录音后，上面几层（标题 / 播放器 / 工具栏）定住不动，笔记和逐字稿各自在自己的框里滚。所以**边听边看笔记时播放器永远在**，滚到笔记第 200 段也不会发现音频条跑没了。改之前六层全铺在一个滚动区里，1280×800 的笔记本上正文第一句要滚到 y=538 才看见（一屏 800 里有三分之一被头几层吃掉）
- **第一次打开有新手引导**：装完第一次启动，会问一遍「本地还是云端」→ 云端的挑服务商、给注册二维码和申请 Key 的图文步骤，填完直接写进设置 → 再选转写模型和 AI 润色模型 → 最后看用户协议。**协议必须滚到底那个勾选框才能点**，不同意就整套服务退出，不留半个界面。不想自己挑就点「自动检测」，它看内存和有没有显卡替你选一档，并告诉你为什么这么选。引导里**不下载模型** —— 选完就进主界面，模型在第一次转写时才开始下，这样不会让人对着进度条干等 2GB

## 三、快速开始

**双击 `启动.vbs`** —— 就这样。

它会在后台悄悄把服务跑起来（没有命令行黑框），等它就绪后弹出一个**无地址栏的应用窗口**，跟普通桌面软件一样：任务栏有独立图标，窗口标题是「讲义笔记 · LectureNotes」。

- 想关掉：窗口里 **设置 → ⏻ 退出服务**，或者双击 `停止.vbs`。
- 关掉应用窗口 ≠ 关掉服务（服务会继续在后台待命，下次打开秒开）。真要退出用上面两个办法。
- **手机传录音要手动开一下**：默认关着「手机访问」（设置 → ④ 手机访问），要传的时候打开，页面会给出形如 `http://192.168.1.23:25994/8gvqzxe4nv/` 的地址；传完记得关掉。关着的时候，就算别人知道地址也只会看到 403，一个字节都读不到。打开之后手机那边**只有一个上传按钮**，别的一样都没有（见下面「手机上为什么只有上传」）。

### 手机访问为什么默认是关的

「默认对局域网敞开」本身就是个坑：校园网、宿舍公共 Wi-Fi 下，同网段的任何人都扫得到这个端口。以前双击启动器就无条件对外开放，用户根本不知道；唯一的屏障是地址里那串钥匙，而地址会被截图、被发到群里。

现在的做法：

- 服务的端口仍然照常监听着（不然开关要重启进程才生效，体验太差），但**非本机请求一律 403**，只在 `config.lan.enabled = true` 时放行；
- 开关在 **设置 → ④ 手机访问**，点了立刻生效，不用重启；
- 关着的时候，手机打开会看到一句「这台电脑关着「手机访问」。请在电脑上打开 设置 → 手机访问 再试。」—— 比回 404 更不容易让人以为程序坏了；
- 开关只能在跑服务的那台电脑上点（手机上点了会被拒），否则等于把门钥匙挂在门上。

### 地址为什么这么长

每台电脑第一次启动时，程序会自己挑一个随机端口（20000–39999）、再随机生成一串「入口钥匙」，记在 `data/instance.json` 里，以后一直沿用。所以：

- 两台电脑装同一份程序，地址天然不一样，不会串台；
- 局域网里的设备打开 `http://192.168.1.23:25994/` 只会看到 404 —— 必须带上 `8gvqzxe4nv` 这一段才进得去；
- 钥匙只存在本机文件里，不上报、不联网。**别把它发给不相关的人**，谁拿到谁就能访问这台机器上的录音。

本机（`127.0.0.1`）访问不需要钥匙，双击 `启动.vbs` 会自动带上。

### 想用命令行 / 想改端口

```powershell
.\start.cmd                      # 有控制台窗口的经典方式（用这台机器自己的随机端口）
.\start.cmd --port 8899          # 换端口
.\start.cmd --host 127.0.0.1     # 端口只绑本机，连「手机访问」都开不了
```

> 开关和 `--host` 是两件事：`--host 0.0.0.0` 决定端口绑在哪（外面能不能连到），`设置 → ④ 手机访问` 决定外面的人能不能进来。启动器用的是 `--host 0.0.0.0`，所以开关能正常工作；如果你自己用 `--host 127.0.0.1` 起服务，那个开关会直接告诉你「这个服务启动时只绑了本机」。

> 没有 Node 也能跑：`start.cmd` 会自动去找系统里的 Node；找不到就用 DSH Desktop 自带的 Electron Node 运行时；两者都没有时会提示你去 nodejs.org 装一个。
>
> `启动.vbs` 用的是 Edge / Chrome 的 `--app` 模式来实现无边框窗口（Windows 10/11 一定装着 Edge），所以不需要额外下载任何东西。启动器不写死端口，它从 `data\runtime.json` 里读服务报上来的端口和钥匙；端口万一被别人占了，服务会自己换一个并记回 `instance.json`。

## 四、推荐的使用流程

1. **上课时**：打开手机自带的「录音机」，按一下开始录，整节课别停。
2. **回到宿舍**：手机连上和电脑同一个 Wi-Fi，在电脑上打开 **设置 → ④ 手机访问** 把开关打开，记下（或点 ⧉ 复制）那个地址。
3. **手机浏览器**打开那个地址 → 点「选择音频文件」→ 选中刚录的文件 → 起个名字 → 点「创建」。手机上只做这一件事，传完会提示「已上传」。**传完回电脑把开关关掉。**
   （也可以直接微信/数据线把文件传到电脑，在电脑页面上导入。）
4. **电脑浏览器**打开同一条录音 → 点 **① 开始转写** → 等它跑完。**笔记会自动生成**，不用再点。「重新生成笔记」是留给「想按新设置重做一份」的时候用的。
5. 点 **导出 Word** 或 **导出 PDF**，就是一份排版好的复习笔记；复习时点笔记里的时间戳就能回听原话。
   （PDF 用的是本机浏览器（Chrome / Edge）的打印引擎，字体是嵌入的子集，一部 52 分钟的课大约 3 页、300 KB。没装 Chrome/Edge 的机器上会明确告诉你导不了，不会给你一个满屏方框的文件。）

> 为什么不让手机直接转写？浏览器在 `http://` 页面里没有麦克风权限，而且本地 Whisper 需要 WebGPU，手机跑不动。所以分工是：**手机负责录和传，电脑负责转和整理**。

### 手机上为什么只有上传

手机上（也就是用局域网地址打开时）界面只剩「选择音频文件」这一个动作，录音、设置、多选、示例、转写、笔记、导出全部不显示。

理由很实在：手机上**确实干不了**这些事 —— 转写要么跑本地 Whisper（手机跑不动），要么走云端（在手机上等几分钟不如回电脑点一下）；导出 Word / PDF 也要在电脑上才拿得到文件。摆一堆点不动的按钮只会让人以为程序坏了。

判断依据是**这个请求是不是从跑服务的那台电脑发出来的**（服务端 `/api/health` 的 `local` 字段），不是屏幕宽度。所以把电脑窗口拉窄不会变成手机版 —— 那台机器什么都能干，没理由削掉一半功能。

手机上还会：不弹打赏窗、不弹协议窗（协议是电脑那边签的，手机上那份正文服务端根本不下发）、列表里不显示置顶/删除/笔记设置这三个按钮（它们平时靠鼠标悬浮才冒出来，触屏上点不出来）。

## 五、两种转写方式怎么选

| | 本地转写（默认） | 云端转写 |
| --- | --- | --- |
| 费用 | 免费 | 按量付费（硅基流动 SenseVoice 免费，Qwen3-ASR 约 ¥0.8/小时） |
| 隐私 | 音频不出本机 | 音频会发给服务商 |
| 速度 | 看模型也看有没有显卡，一小时课 8 分钟到 3 小时（下面有实测表） | 通常 1–3 分钟/小时录音 |
| 精度 | tiny/base 能读，small 够用，large-v3-turbo 最好 | SenseVoice 中文很好、免费；Qwen3-ASR 认字更准 |
| 适合 | 隐私敏感、短录音 | 长录音、追求速度 |

本地转写不用选服务商——在设置里服务商选「本地」，下面的「本地转写模型」卡片就是浏览器 Whisper 的四档。**每张卡最后一行写的是推荐配置**（要不要显卡、内存多大），照着机器挑就行；首次用会下载模型（96MB 到 1.9GB），之后浏览器会缓存。

四档的实测数据（同一段 60 秒课堂音频，本机 RTX 5060 笔记本 + 8 核 CPU 实测）。**这张表只放在文档里，卡片上不写耗时**——买家看的是「我这台机器跑不跑得动」，不是「3.0× 实时」这种只有作者看得懂的数：

| 模型 | 体积 | 参数量 | 纯 CPU | 有显卡 | 适合 |
| --- | --- | --- | --- | --- | --- |
| `tiny` | 96MB | 39M | 4.2× 实时 | 11× 实时 | 老机器急用，错字明显偏多 |
| `base` | 172MB | 74M | 3.0× 实时（**默认**） | 跑不了（见下） | 大多数电脑，20 分钟出一小时课 |
| `small` | 521MB | 244M | 1.4× 实时 | 跑不了（见下） | 要更准又没显卡 |
| `large-v3-turbo` | 1.9GB | 809M | 0.3× 实时（三小时多） | 7.7× 实时 | 有独立显卡的机器 |

> **为什么 base 和 small 不用显卡？** 实测这两个模型在 WebGPU 上跑的是 fp16，结果要么是一屏乱码、要么干脆空输出（2 秒「转完」两分钟音频，根本没在编码）；换成 GPU + q8 又只有 0.17×，比 CPU 还慢三倍。所以这两个模型会自动走 CPU，界面上会提示一句「这个模型在显卡上跑不出正确结果，改用 CPU」。这不是限制，是它们本来就不适合显卡。

`medium` 没有列进来：CPU 上内存不足（报 `Error 1267168960`）、显卡上也报错，两种设备都跑不起来。

模型默认从 **hf-mirror.com**（国内镜像）下载，依赖库默认用 jsDelivr；这两个源不通时会自动换备用源（npmmirror / unpkg / HuggingFace 官方）。

### 服务商只有四家，模型跟服务商绑定

设置里的「服务商」下拉只有四项，而且**四家全部能同时做转写和 AI 笔记**：

| 服务商 | 转写模型 | 笔记模型 |
| --- | --- | --- |
| 本地（免费、不上传） | `onnx-community/whisper-base`（默认，172MB）/ `whisper-tiny`（96MB）/ `whisper-small`（521MB）/ `whisper-large-v3-turbo`（1.9GB） | `qwen2.5-3b`（默认，1.8GB）/ `qwen2.5-7b`（4.4GB）/ `qwen2.5-14b`（8.4GB）/ `qwen2.5-32b`（18.5GB）—— 需先在 ⑤ 环境自检里部署运行时 |
| 硅基流动 SiliconFlow | `FunAudioLLM/SenseVoiceSmall`（免费，默认）/ `Qwen/Qwen3-ASR-1.7B`（约 ¥0.8/小时） | `Qwen/Qwen2.5-7B-Instruct`（默认，一节课一两分钱）/ `Qwen/Qwen3-30B-A3B-Instruct-2507` / `deepseek-ai/DeepSeek-V3` / `zai-org/GLM-5.3-Flash`（便宜，但不是免费的） |
| OpenAI 官方 | `whisper-1` | `gpt-4o-mini`（默认）/ `gpt-4o` |
| 自定义（自建/中转） | 自己填 | 自己填 |

**为什么收成四家**：以前有十一家，其中七家只能做一半（DeepSeek 只能笔记、Groq 只能转写）。用户第一步就得先算「这家能不能干这个活」，界面还得为两种能力各准备一套模型列表。收完之后只剩一个下拉，选完这一家，下面**只显示这一家真正能调的模型**，不会出现「把别家的模型名填进来，请求直接 400」这种坑。

那些被收掉的服务商（DeepSeek、阿里云百炼、智谱 GLM、Moonshot Kimi、Groq、Ollama、LM Studio）全部收进「自定义」，它们本来就是 OpenAI 兼容接口。老配置升级时会自动迁移过去，地址和模型名保留、Key 不用重填。

设置里的转写模型、笔记模型都是**卡片选择器**：每张卡写着档位和一句话质量说明，当前用的那张有蓝框和「现在用：xxx」。想填预设里没有的型号，点最后一张「其他（自己填）」。

**本地转写那四张卡是例外：不贴任何标签**。四档全是「零成本」，同一个徽章重复四遍等于没说；它们真正的差别（要不要显卡、内存多大）写在卡片最后一行。云端模型的档位徽章保留 —— 那里 free / 便宜·够用 / 便宜·好用 / 偏贵·更好 四档确实在区分真实的钱和质量。

**档位一个标签说两件事**——贵不贵、好不好，省得自己算：

| 档位 | 意思 |
| --- | --- |
| **零成本** | 不花钱，在本机跑（本机 qwen2.5-7b） |
| **便宜·够用** | 花得很少，日常课堂够用（Qwen2.5-7B、gpt-4o-mini、SenseVoice） |
| **便宜·好用** | 花得少、质量也稳，多数课选它就对了 |
| **偏贵·更好** | 贵一档，长课少漏考点（DeepSeek-V3、gpt-4o） |

卡片第二行只讲这个模型**好在哪**，不写价格、也不列缺点 —— 收不收费看徽章就够了，具体金额在「七、花多少钱」里。那句话刻意写得像人写的：短、只谈速度和准度，比如转写的两张是「速度快，准确度略低」和「较慢，准确性高」，不会出现「不思考直接答，一份笔记几十秒就出来」这种机器腔。

**DeepSeek-V3 那张还多一个「作者推荐」小标签**——它不是第五个档位，是「我试下来最常用的那个」的背书，所以做成实心深色块、跟在档位后面，一眼能分出来。

> **GLM-5.3-Flash 有个坑，已经堵了**：它是「先想再答」的思考型模型，而且想得特别久 —— 一份两万多字的逐字稿放任它想要跑 **810~822 秒**，而 Node 内置的 fetch 有 **300 秒**响应头超时硬墙，于是界面永远只显示「LLM 请求失败: Headers Timeout Error」。现在服务端调它时会自动带 `reasoning_effort: low`（实测 **160 秒**，思考归零，要点条数没变少），同一条录音的完整 AI 润色从「303 秒后失败」变成「122 秒成功」。只有 `low` 真管用，`enable_thinking:false` / `thinking:{type:'disabled'}` / `reasoning_effort:'none'` / `chat_template_kwargs` / `thinking_budget:0`（直接 400）/ `reasoning_effort:'minimal'` 六种写法实测**都关不掉**思考。

## 六、可选：接上大模型，笔记更好读

默认的**离线引擎**（不联网、不要 Key）会在本地做：主题分段 → TextRank 挑重点 → 关键词/定义/考点/作业抽取 → 自测题生成。够用，但句子是老师的原话（口语）。

接上大模型后，点 **AI 润色** 会把口语整理成书面复习资料，长录音会自动分块总结再汇总，不会爆上下文。

在 **设置 → ① 服务商** 里选一家，转写和笔记共用这一家、同一把 Key。也可以选「自定义」手填地址：

> Qwen3 系列会「先思考再回答」（实测一句「说好」就花了 300~400 个思考 token，而那些字也算钱），慢且贵；Qwen2.5-7B-Instruct 和 DeepSeek-V3 是直接出答案的，做笔记更划算。

### 笔记风格、重点条数、提示词：每条录音各自一份

这三项不在设置里，**在新建录音的弹窗里**（导入文件时弹、录完音点「停止并保存」时弹）：

| 项 | 说明 |
| --- | --- |
| 录音名 | 默认取文件名 / `课堂录音-202610231430`，可以改成「第 8 讲 · 图论」这种 |
| 提示词 | 只对这条录音生效。比如法学课写「法条编号写全，重点用【】标出」，高数课写「公式推导别跳步」。**留空 = 用设置里的通用要求**（设置里已经没有这个框了，但老配置里存的值仍然生效） |
| 笔记风格 | 应试重点版 / 提纲版 / 康奈尔版 |
| 每个主题几条重点 | 默认「自适应」（按主题长短定 2~8 条）；也可以钉死 3 / 5 / 6 / 8 / 10 条。**离线笔记和 AI 润色都认这一项**（AI 润色是把条数写进提示词，让模型照做） |

为什么挪出来：这些设置**每条录音都不一样**。一门法学课要「法条编号写全」，一门高数课要「推导别跳步」，放在全局设置里就只能二选一。

选错了也不要紧 —— **左侧录音列表每行最右边有个「⋯」**（就这一个入口，别处没有），鼠标移上去它变成「编辑」两个字，点开就是这条录音的笔记设置（风格 / 重点条数 / 提示词，连录音名也能一起改）。不用先打开录音，在列表里看到哪条想调就点它。悬停时那个按钮的提示里还会写出「现在是「应试重点版 · 5 条重点」」。手机上不能悬浮，所以那边直接显示「编辑」两个字。

> 「⋯」为什么放在钉图和删除的**右边**：那两只是在整行悬浮时才冒出来的，如果「⋯」在它们左边，一悬浮它们挤出来就会把「⋯」往左推——鼠标旁边的按钮忽然换位置最容易点错。放最右边它就一直钉着不动。

改完点保存，**已经生成过的笔记不会自动重写**：想按新风格重做，再点一次「重新生成笔记」或「AI 润色」。

批量导入多个文件时只弹一次窗，风格和提示词套用到这一批全部（同一批拖进来的通常就是同一门课），录音名仍按各自的文件名走。

## 七、数据在哪、隐私如何

```
data/                        # 默认在 %LOCALAPPDATA%\LectureNotes\data\
├── config.json              # 设置（含 API Key，明文存在本机）
└── lectures/<id>/
    ├── meta.json            # 标题、课程、时长、状态
    ├── audio.m4a            # 原始录音
    ├── transcript.json      # 逐字稿（带时间戳）
    └── note.json            # 笔记 Markdown
```

- 所有内容都在本机 `data` 目录里，**整个目录拷走就是完整备份**。
- `data` 目录在哪？**默认在 C 盘**（跟其它软件一样）：`%LOCALAPPDATA%\LectureNotes\data\`。装完之后设置 → ③ 存储位置 里两个路径框写的就是真实位置，可以直接看。
- 想让数据跟着程序走（绿色版 / 装 U 盘），在程序目录里自己建一个 `data` 文件夹就行 —— 程序是**看到 `data` 才用它**，不会自己凭空建一个。所以解压到移动硬盘也不会在上面长出数据目录。
- 用本地转写时，音频一个字节都不会离开你的电脑。
- 用云端转写或 AI 笔记时，只有音频 / 文字会发给你自己填的那家服务商。
- API Key 存在 `data/config.json`，只在服务端使用。本机打开设置能看到原文（方便复制、换机器），手机或局域网访问时只下发掩码。
- 多个 Key 会存一份清单，设置里可以从下拉框切换。

### 录音和模型缓存可以换盘（设置 → ③ 存储位置）

`data` 目录里最占地方的是两块，都可以在设置里搬到别的盘：

| 位置 | 默认路径 | 大概多大 | 说明 |
| --- | --- | --- | --- |
| 录音 | `data/lectures/` | 随录音增长，一小时约 30 MB | 每条录音一个文件夹，含音频 + 逐字稿 + 笔记 |
| 模型缓存 | `data/models/` | 3~4.5 GB | 本地转写要用的 Whisper 模型，第一次用才下载 |

用法：路径框里显示的是**当前实际位置**（默认状态下就是 `data\lectures` 的绝对路径）。改到别的盘，直接把路径改掉 → 点旁边的「迁移」。路径框右边有四个按钮：

| 按钮 | 做什么 |
| --- | --- |
| 复制（双矩形图标） | 把这个路径复制到剪贴板，方便粘到资源管理器地址栏 |
| 打开（文件夹图标） | 在资源管理器里打开这个目录（只认「录音」和「模型缓存」两处，传别的路径一律不认） |
| 迁移 | 把现有文件复制到框里填的新位置，流程见下 |
| 重置 | 改回默认位置（**只改指向，不搬文件**） |

迁移的流程是**先验证、再复制**：

1. 先检查路径能不能用（盘符存不存在、能不能写、是不是完整路径）。检查不过就当场告诉你原因，配置文件一个字节都不动。
2. 给你看目标位置**现在有多少东西**。不为空会提示「会和现有内容合并」，避免把两次的数据混进同一个目录。
3. 你点确认后才开始复制。
4. **只复制，不删除源目录。** 这一点是刻意的：机器休眠、断电、中途关窗口都可能让复制只做一半，而录音没法重录。宁可留一份占地方，也不冒这个险。界面会明确告诉你旧目录在哪，确认新位置没问题后自己删。

改回默认：点「重置」。它只改配置，**不会把文件搬回去** —— 搬回通常是「从移动硬盘回 C 盘」，万一 C 盘空间不够会写到一半失败，比不搬更糟。所以搬家这一步留给用户自己决定。

**几个必须知道的边界：**

- 迁移**不进配置文件就不生效**，`data/config.json` 里 `storage.lecturesDir` / `storage.modelsDir` 是空串就代表用默认位置。
- 路径框里的字**要在改过之后点「迁移」或「保存」才算数**。只改字不发请求，跟没改一样（这是为了防手滑：输入框里那个路径可能是你改到一半的）。
- 配置里的路径**下次启动时验证一次**。如果那时盘没插（比如迁到移动硬盘又拔了），服务不会起不来 —— 会退回默认位置并把这个情况写到 `/api/system` 的 `storage.<x>.error` 里，设置面板上会用红字显示「你填的用不了，现在用的是……」。**这时候新录音会存到默认位置**，别以为还在移动硬盘上。
- `data` 目录本身（`config.json`、`instance.json` 这些）**不能**在界面上改，它决定配置存在哪 —— 想改只能命令行 `--data`。
- **手机/局域网只能看、不能改**：这节的输入框、迁移、重置、打开四个按钮在手机上是禁用的，顶部文案会换成「只能在跑这个服务的那台电脑上改」，下面照常显示那台电脑现在的实际位置。服务端那三个接口（`/storage/check` `/storage/move` `/storage/open`）本来也只认本机（非本机回 403），这是双保险。**尤其是那个「打开」按钮** —— 手机上点一下就在别人电脑上弹资源管理器窗口，这种事不能发生。

## 七之二、费用与打赏

这个软件本身是**免费**的，装好就能用全部功能，没有试用期、没有功能阉割、没有登录。

会花钱的只有两处，都由你自己决定要不要开：

- **云端转写**：按音频时长计费，钱付给你选的那家服务商（比如硅基流动）。用本地 Whisper 转写就一分钱不花。
- **AI 笔记**：按 token 计费，同样付给你选的服务商。用默认的离线引擎就一分钱不花。

如果它确实帮你省下了抄笔记的时间，设置里有个「请人家喝奶茶」——可以打赏，**不打赏也一点功能都不会少**。

打赏的收款码是图片文件，放在 `public/donate/` 下：

```
public/donate/wechat.png     # 微信收款码
public/donate/alipay.png     # 支付宝收款码
```

两个都放就并排显示，只放一个就只显示一个，一个都没放会显示一句说明。改完不用重启服务，刷新页面就生效。

**图片必须是只有二维码的方图。** 微信/支付宝 App 里存的整张竖版海报不能直接放：那种图上下有大标题和留白，二维码只占中间一小块（实测微信海报 828×1128，二维码只有 362×360），界面上按 220px 显示后码只剩 96px，手机扫不出来。用截图工具只框住二维码本身、四周留一格白边存成正方形即可，`public/donate/README.txt` 里也写了这条。

## 七之三、装完之后怎么升级、加新功能怎么同步给用户

先说结论：**程序和你的数据是分开的两个目录**，所以升级只是换程序，录音和设置一个都不会动。

```
C:\Program Files\LectureNotes\            ← 程序（升级时整个换掉）
%LOCALAPPDATA%\LectureNotes\data\         ← 你的录音、逐字稿、笔记、配置（升级不碰）
```

这条不是碰巧，是安装脚本里的 `[Dirs]` 和 `[UninstallDelete]` 特意这么写的：卸载只清程序目录里的临时文件，绝不碰用户目录。

### 发新版的时候，用户要做的事

只有一步：**下载新的安装包，双击，装到同一个位置**。

- 安装包会用同一个 AppId 认出「这是升级，不是新装」，不会重复问你装到哪；
- 装完会提示「这个目录不会因为卸载被删除，重装或升级后会自动接着用」；
- 实测：覆盖安装 5 秒完成，`config.json`（含 API Key）、录音、逐字稿、笔记、你手动放进数据目录的文件**全部原样保留**；
- 桌面 / 开始菜单快捷方式指向程序目录，自动就是新版本。

### 版本号怎么保证不越装越旧

`server.mjs` 顶部 `const VERSION = 'x.y.z';` 与 `packaging/lecture-notes.iss` 的 `#define AppVersion "x.y.z"` 必须一致，`packaging/build.ps1` 每次打包都会核对，不一致直接拒绝出包。发新版只改这两处。

### 现在还没有的部分（如实说明）

- **没有自动更新**：程序不会自己去网上查有没有新版，用户得自己下载。要做到「点一下自动升级」得先有个放安装包的地址（自己的网站或 GitHub Releases），再在程序里加一个「检查更新」按钮 + 下载 + `静默安装`。工作量不大，但需要一个发布的服务器。
- **没有错误上报**：崩溃了作者收不到任何信息，只能靠用户反馈。
- **升级不改数据格式**：如果以后改了 `transcript.json` / `note.json` 的字段，老数据靠 `data/lectures/*/transcript.json` 里的 `schemaVersion` 和 `note.json` 里的 `noteVersion` 自动识别并就地升级（这一层已经在 `public/transcript.js` 和 `public/note.js` 里，读写都会过一遍）。**意思是：以后加新功能改格式，老用户打开就自动修好，不用手动迁移。**

### 重点提取是怎么做的（`public/summarize.js`）

没有用任何模型，纯统计 + 语言学启发式，中文和英文混排都能处理：

1. **分句**：中文按 `。！？；`，英文句点要求「前一字符是字母 + 后一字符是空白」，所以「习题 6.3 到 6.8」不会被切开。
2. **语义单位**：不依赖分词器，用「汉字 bigram + 英文单词」当特征，避免中文分词错误传导到后面所有环节。
3. **主题分段**：算相邻句子的词汇衔接度，在低谷处切分；同时识别「接下来 / 第二个问题 / 最后」这类结构提示词；并且**不会在「第一…第二…第三…」的分条列举中间切开**。主题标题由该段的高分关键词自动命名。
4. **关键词**：`词频^0.62 × 逆句频 × 长度权重 × 边界自由度 × 独立成词率`。
   - *边界自由度*（左右邻居的熵）负责干掉「叉树的」「代码就」这种切错边界的碎片；
   - *独立成词率* 负责干掉「间复杂度」这种其实是「时间复杂度/空间复杂度」一半的碎片。
5. **重点句**：TextRank 全局重要性 × 关键词命中 × 线索词加权（`重点是` `考点` `会考` `注意` `记住` `因此` `例如`…）× 位置先验，再用相似度做冗余惩罚，保证每个主题下的重点不重复。每主题取几条由「自适应」算（`autoPoints()`，按该主题句数 `round(log2(n)×1.2)`，夹在 2~8 条），也可以手动指定。**AI 润色不走这条算法，但「重点条数」同样生效**：条数会写进提示词（`public/llm.js` 的 `pointsRule()`），选 3 条就让它每个主题正好写 3 条，选自适应就让它按主题篇幅在 2~8 条之间自己定。
6. **结构化抽取**：概念定义（`所谓X，是指Y` / `X 称为 Y`）、分条列举、老师强调、考点、作业安排。
7. **自测题**：从重点句和定义按模板生成「什么是X」「X包含哪几点」「X的原因是什么」这类问题。

## 十二、已知限制 / 常见问题

### 「转写失败：Failed to fetch」是怎么回事

这是踩过的坑，已经修好了，记在这里免得以后重现：

1. **`env.remoteHost` 少了结尾斜杠** —— transformers.js 是拿它和 `{model}/resolve/{revision}/` 直接做字符串拼接的，少了斜杠会拼成 `https://hf-mirror.comXenova/...` 这种不存在的地址。
2. **浏览器 CORS** —— 就算地址拼对了，hf-mirror 的 `/resolve/` 端点只允许它自家域名跨域（响应头是 `Access-Control-Allow-Origin: https://hf-mirror.com`），浏览器从 `127.0.0.1` 请求一定被拦。
   **解决办法：模型文件走本机服务中转。** 浏览器请求同源的 `/api/hf/<owner>/<model>/resolve/...`，由服务端去取（Node 不受 CORS 约束），并在 `data/models/` 留一份磁盘缓存，下过一次就永远不用再下。
3. **transformers.js v4 的 dist 里没有 ONNX 运行时的 wasm**（只有一个 46KB 的加载器），而 v3 的 dist 里带着 21.6MB 的 `ort-wasm-simd-threaded.jsep.wasm`。所以默认 CDN 固定在 **v3**，硬指 v4 会在推理初始化时失败。

现在这三处都有自动兜底和明确的报错文案，不用再靠猜。真机验证见 `tests/asr-check.mjs`。

### 长录音转写很慢

浏览器本地转写的速度取决于**有没有用上显卡**：

- 进度条显示「模型已就绪（**显卡加速**）」= 走 WebGPU，大约 5–15 分钟/小时录音；
- 显示「（**CPU，会很慢**）」= 退回 WASM，实测比实时还慢约 4 倍，一小时录音要几个小时。

CPU 模式下请改用云端转写，或在设置里换更小的模型（`Xenova/whisper-base` / `tiny`）。
另外超过 45 分钟的录音，点「开始转写」时会先弹一次确认，告诉你大概要等多久，不会再出现「看起来卡死其实在跑」的情况。

### 其它

- **首次转写要先下模型**：几十 MB 到 1.5 GB，走本机中转 + 磁盘缓存，下过就不用再下。缓存位置 `data/models/`，可以直接看/删。
- **很长的录音注意内存**：本地转写要把整段音频解码进内存，1 小时立体声约 1 GB。
- **转写准确率取决于录音质量**：坐前排、别翻书、别说话，比换大模型有用得多。
- **自动提取的重点一定会有遗漏**：它是启发式的，用于「快速抓住课堂骨架」，请对照逐字稿核对。
- **端口被占用**：`start.cmd --port 8899`。
- **手机打不开局域网地址**：检查是不是同一个 Wi-Fi、电脑防火墙是否拦了 Node。
- **改了代码但界面没变**：静态资源已设成 `no-store`，正常刷新即可；实在不行 Ctrl+Shift+R 强刷。

- **本机转写要先下模型**：首次 96MB 到 1.9GB，慢是正常的，之后走浏览器缓存。国内请保持「模型下载源 = hf-mirror.com」。
- **没显卡的电脑别选 large-v3-turbo**：它在纯 CPU 上只有 0.3× 实时，一小时课要跑三小时多。默认的 `base` 是 3.0×（约 20 分钟），先用它试试；嫌不准再换 `small`（约 44 分钟）。
- **不知道选哪个就看卡片上写的时间**：那是本机实测值，不是估算。`tiny` 最快但错字多，`base` 最省事，`large-v3-turbo` 要有独立显卡才划算。
- **很长的录音注意内存**：浏览器本地转写要把整段音频解码进内存，1 小时立体声约 1 GB。超过 90 分钟建议按节次分开录，或改用云端转写（单文件请控制在 200MB 以内）。
- **转写准确率取决于录音质量**：坐前排、别翻书、别说话，比换大模型有用得多。
- **自动提取的重点一定会有遗漏**：它是启发式的，用于「快速抓住课堂骨架」，请对照逐字稿核对。笔记末尾的「需要回听核对的地方」就是留给这件事的（网页上看得到，导出 Word / PDF / Markdown 时会去掉）。
- **端口被占用**：`start.cmd --port 8899`。
- **手机打不开局域网地址**：检查是不是同一个 Wi-Fi、电脑防火墙是否拦了 Node。
- **云端转写报文件过大**：服务商的单文件限制各不相同（OpenAI 是 25MB），太长就改用本地转写或先切段。
