提示条款
════════════════════════════════════════════════════════════════════

作者非常重视你的录音、笔记与个人信息。在开始使用之前，请你花
几分钟读完这份政策，它会告诉你：

  · 你的数据存在哪、谁看得到；
  · 什么情况下数据会离开你的电脑；
  · 本软件到底会连哪些网；
  · 你可以怎么删除、搬走、清空你的数据。

本政策是《用户协议》的组成部分，与《用户协议》具有同等效力。

一句话总结：**录音和笔记只存在你自己的电脑上，作者没有任何
服务器，看不到、也拿不到你的任何数据。**

一、本政策的适用范围
════════════════════════════════════════════════════════════════════

1.1 本政策适用于「讲义笔记」在你的电脑上运行、并处理你的录音、
    逐字稿、笔记与设置的全过程。

1.2 本政策不适用于第三方服务商。你一旦选择云端转写或云端 AI
    笔记，数据就会进入该服务商的系统，如何处理由该服务商自己的
    隐私政策决定。作者无法介入，也不对其处理行为负责。

1.3 本政策不适用于第三方开源组件自身的行为。这些组件在你的电脑
    上运行，作者已核查它们不会主动上报数据（见第七条），但它们的
    行为最终由其许可方与源码决定。

二、谁在处理你的数据
════════════════════════════════════════════════════════════════════

2.1 **唯一的处理者是你自己。** 本软件是一段跑在你电脑上的程序，
    作者不是它的运行方，无法远程访问它，也无法远程干预它。

2.2 作者不掌握你的：录音、逐字稿、笔记、导出文件、API Key、
    机器配置、使用记录、IP 地址、设备标识。

2.3 你与本软件之间没有任何账号体系，也没有任何登录行为，因此
    不存在「账号信息」这一类数据。

三、数据存在哪里
════════════════════════════════════════════════════════════════════

3.1 默认位置：

    %LOCALAPPDATA%\LectureNotes\data\

    也就是 C:\Users\<你的用户名>\AppData\Local\LectureNotes\data\

3.2 如果程序目录里已经存在一个可写的 data 文件夹（例如你做过
    绿色版、或从旧机器连数据一起拷过来），程序会优先使用它：

    程序目录\data\

    判断规则是「**看到 data 才用**」，而不是「能写就自己建一个」。
    所以你把程序解压到移动硬盘或 U 盘上，它不会在上面凭空长出
    一个数据目录。

3.3 你也可以在「设置 → ③ 存储位置」里改：录音目录与模型缓存目录
    可以各自搬到别的磁盘。搬动采用「复制后校验，不删源」的方式，
    确认新位置可用之后才切换，不会出现搬到一半源文件已经没了的情况。

3.4 数据目录里有哪些东西：

    lectures\<录音 id>\
        audio.*          你的原始音频
        transcript.json  逐字稿（含每句的时间戳）
        note.json        结构化笔记
        meta.json        标题、创建时间等元信息

    models\              下载到本地的转写模型文件
    config.json          你的设置、API Key、各服务商参数
    instance.json        本机服务的端口与入口钥匙
    runtime.json         服务运行时的进程号与访问地址
    local-llm-path.txt   本机大模型部署在哪儿的路径记录
    install-agreed.txt   安装时点了「接受」留下的时间戳

    state.json 是早期版本留下的文件，现在已经不读也不写，可以删掉，
    删掉不影响使用。

3.5 这些文件都是普通文件，你可以用资源管理器直接打开、复制、
    备份、删除。本软件没有使用数据库，也没有加密存储。

3.6 卸载软件**不会**删除这个数据目录。想彻底清除，请自行删除
    整个 LectureNotes 文件夹（见第八条）。

四、什么时候会联网
════════════════════════════════════════════════════════════════════

只有在下面这些情况下，本软件才会主动发起网络请求。除此之外，
它不会主动联网。

4.1 你选了云端转写，并点击「开始转写」

    你的音频文件会被发送给你配置的那家服务商（例如硅基流动）。
    请求直接发往该服务商公开的 API 地址，作者不在中间，也没有
    任何中转服务器。

4.2 你选了云端 AI 笔记，并点击「生成笔记」

    逐字稿的文本会发送给你配置的大模型服务商。发送内容包含逐字稿
    正文、时间戳，以及你选择的笔记风格等参数。

4.3 你选了「浏览器本地转写」

    第一次使用时，浏览器要从 CDN（jsdelivr、unpkg、npmmirror 等）
    加载转写引擎的脚本，并从 hf-mirror.com（Hugging Face 的国内
    镜像）下载模型文件。模型下载会经本机服务转发，以避免浏览器的
    跨域限制。

    这些都只是**下载**，不会上传你的任何内容。加载完成后，转写
    全程在你的电脑上完成，可以断网使用。

4.4 你在设置里点了「测试连接」

    会向你填写的接口地址发送一个极小的试探请求，用于验证 Key 与
    网络是否可用。该请求不包含你的录音或笔记内容。

4.5 本软件检查有没有新版本

    本软件**有**自动更新功能，但它问的只是「有没有新版本」，不发送
    任何关于你、关于你的录音或笔记的信息。

    什么时候会问：
    · 你打开设置面板时，顺手问一次；
    · 你点「检查更新」时，立刻问一次。

    问到哪去：默认问 GitHub Releases 的公开接口
    （api.github.com，国内连不上时改用 gh-proxy.com 镜像）。
    如果你在配置里换成了自己的更新地址，就问那个地址。
    请求内容只有版本号与固定的一句 User-Agent，例如
    User-Agent: LectureNotes/0.9.0，不带任何标识符。

    多久问一次：同一个版本在 6 小时内只会真正发起一次请求，
    其余时候直接用上次的结果，一个字节都不发出去。这个节流记录
    存在本地 config.json 的 update.lastCheckAt 里，不上报给任何人。

    发现了新版本之后：先在设置里给你看一行提示，**不会自己下载、
    更不会自己安装**。你点「下载并安装」才会下载安装包，下完之后
    还要再点一次「立即安装」才会真的装 —— 因为装之前必须先退出
    本软件，这一步必须由你明确同意。

    安装包从哪来：从上面那个公开地址下载，存在数据目录的
    update\ 文件夹里。下载时会核对文件大小，对不上就不会被当成
    安装包使用。

    不想被问：config.json 里 update.enabled 改成 false，本软件就
    再也不会发起这个请求。

4.6 你的手机或平板通过局域网访问本软件的网页界面

    这是你自己电脑上的服务在接受连接，数据没有离开你的局域网。
    详见第六条。

4.7 本软件**没有**以下行为：

    · 没有埋点，不上报点击、停留、功能使用等任何行为数据；
    · 没有统计，不收集设备数、活跃度；
    · 没有崩溃上报，程序出错时不会把日志发出去；
    · 没有静默更新，不会在后台偷偷下载或替换程序文件；
    · 没有广告 SDK，没有推送 SDK，没有用户画像；
    · 不会读取你的其他文件、浏览器历史、通讯录、剪贴板。

五、API Key 怎么存的
════════════════════════════════════════════════════════════════════

5.1 你填写的 API Key 保存在数据目录的 config.json 里，**明文**。

5.2 为什么不明文加密：程序需要用这把 Key 去调用第三方接口。若加密，
    密钥本身也得存在同一台电脑上，防不住能读文件的程序，只是多一层
    看起来安全的外壳。与其给你虚假的安全感，不如把边界说清楚。

5.3 安全边界：

    (1) 你的电脑上如果有别的程序能读取这个文件，它就能看到 Key。
        安装本软件之前，请先判断这台电脑是否可信。
    (2) 界面只监听本机时，Key 在设置页面上可以直接看到（方便核对）。
    (3) 当你开启「手机访问」让局域网设备访问时：
        · 局域网内的设备看不到 Key 明文，只能看到 sk-abcd…wxyz
          这样的掩码；
        · 修改 Key、读写配置等敏感接口只接受来自本机的请求；
        · 协议正文、数据目录路径等本机信息不会下发到远端。
    (4) 界面与接口都不会把 Key 写进日志文件。

5.4 如果你怀疑 Key 已经泄露，请立刻到服务商控制台吊销并重新生成，
    然后在「设置 → ① 服务商」里更新。本软件提供多把 Key 的保存与
    切换，方便你在换 Key 时不打断正在做的事。


════════════════════════════════════════════════════════════════════
六、入口钥匙与局域网访问
════════════════════════════════════════════════════════════════════

6.1 本软件启动时会在本机随机挑一个端口（20000–39999），并生成一把
    随机入口钥匙。访问地址形如：

    http://192.168.1.4:25994/8gvqzxe4nv/

6.2 没有这把钥匙，局域网内的其他人即使扫到端口，也只会看到
    「页面不存在」。这把钥匙保存在你本机的 instance.json 里，
    不会外传。

6.3 入口钥匙不是强身份认证，它是「防误入」而不是「防攻击」。在
    公共 Wi-Fi、宿舍共享网络、公司内网等环境里，建议关闭「手机
    访问」，或者只在你信任的网络中临时开启。

6.4 「手机访问」默认关闭，需要你在设置里主动打开。打开后，同一
    局域网内的设备可以上传录音、查看列表。手机端只负责上传，不
    提供删除、置顶、笔记设置等操作，也不会显示 API Key。

七、第三方组件与它们的行为
════════════════════════════════════════════════════════════════════

7.1 本软件的本地转写依赖 Transformers.js 与 ONNX Runtime，这两者
    都在你的浏览器里运行，模型文件下载完成后完全离线工作。

7.2 本软件的本地 AI 笔记依赖 llama.cpp，这是一个独立的本地进程，
    通过本机端口通信，不访问外网。

7.3 上述组件均不会主动上报使用数据。但它们由第三方维护，作者无法
    对其未来版本的行为作出永久保证。升级组件时，作者会核查其网络
    行为。

7.4 本软件不接入任何广告、统计、推送、崩溃收集类的第三方 SDK。

八、你如何管理你的数据
════════════════════════════════════════════════════════════════════

8.1 **查看**：数据目录里的文件都是普通文件，可以直接打开。界面上
    也能看到每条录音的标题、时长、转写状态。

8.2 **修改**：录音标题、笔记风格、重点条数等都可以在界面上改。逐字稿
    与笔记也可以手工编辑后重新生成。

8.3 **导出**：笔记可以导出为 Word、PDF、纯文本，导出文件保存在你
    指定的位置。

8.4 **搬移**：「设置 → ③ 存储位置」里可以把录音目录或模型目录搬到
    别的磁盘。搬移采用复制后校验的方式，源文件不会在复制完成前被
    删除。若中途断电或休眠，源数据依然完整，重新搬一次即可。

8.5 **删除单条录音**：在列表里删除即可，会同时删掉该录音的音频、
    逐字稿、笔记与元信息。

8.6 **彻底清除**：卸载软件后，手动删除数据目录（默认
    %LOCALAPPDATA%\LectureNotes\data）即可。删掉之后没有任何副本
    留在别处 —— 作者这边本来就没有。

8.7 **清除浏览器缓存**：本地转写所用的模型文件由浏览器缓存保存，
    占用空间较大时可以在浏览器设置里清理站点数据。清理后下次转写
    会重新下载。

附录：名词解释
════════════════════════════════════════════════════════════════════

数据目录
    存放你全部录音、逐字稿、笔记、设置与模型的文件夹。默认在
    %LOCALAPPDATA%\LectureNotes\data，也可能是程序目录下的 data。

逐字稿
    录音转写出来的文字，带每句的起止时间。它保存在 transcript.json。

笔记
    由逐字稿整理出的结构化内容（分主题、列重点、带时间戳跳转）。
    它保存在 note.json。

API Key
    第三方服务商发给你的访问凭证，形如 sk-xxxxxxxx。它相当于账号
    密码，泄露后他人可用你的账户额度。

入口钥匙
    本软件为局域网访问生成的一段随机字符，拼在网址路径里，用于
    避免同网络内的其他人误入。

掩码
    把 Key 的头尾保留、中间用省略号代替后的形式（sk-abcd…wxyz），
    用于在不暴露完整 Key 的前提下辨认是哪一把。
