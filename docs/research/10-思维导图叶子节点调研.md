# 课堂思维导图的叶子节点该放什么

> 调研时间：2026-11-01　｜　触发问题：导图叶子用 n-gram 抽词，抽出「看一」「道题」「阶档」「冷记记一下」这类 ASR 残渣
> 本文件只写**查到的**和**本机实测的**。查不到的一律标「没查到」。

---

## 0. 结论先行

1. **叶子不能是词，必须是「一句能独立成立的命题」+ 一个类型标签。**
   这不是审美判断，是三家头部产品的共同形态：通义听悟的导图节点是「短句式论断」，Notta 的导图是笔记标题层级的投影（叶子=正文要点句），Otter 干脆把「关键词」和「Outline」拆成两个不同产物。
2. **「公式/结论最重要」在文档上有硬支撑。** 中国高校教学大纲把知识点明确分成「定义、定理、性质、特征」（概念类）与「计算、解法、公式、法则」（方法类）两组，并各配一套掌握程度动词。数学/工科/医学大纲的「教学重点」里，出现频率最高的就是公式、定理、作图步骤、结构特征。
3. **分学科不是加分项，是刚需。** 本机实测：把「公式类」规则套到工程制图课上，命中率 **0.0%**；套到高数课上最高 22.3%。一套规则吃不下所有课。
4. **纯规则能到「能用」的程度，但上限明确。** 本机高数录音实测：公式句规则强候选召回 1.1%–2.6%，样本精确率约 70–80%；而「定义」触发词（什么叫/定义为）在高数课上只命中 0–0.1%——**靠触发词抽定义必然几乎全空**，这条路不能走。
5. **不建议继续在「抽词」上投入。** 中文短文本关键词抽取的公开实测里，TextRank 的精确率在三个数据集上都是最低档（29.6 / 26.0 / 26.4），短文本正是它最差的区间。现在的毛病有论文原话背书，不是参数没调好。

## 1. 业界产品的实际做法：叶子节点到底放什么

### 1.1 逐产品核实结果

| 产品 | 有没有自动导图 | 叶子节点是什么 | 证据强度 |
|---|---|---|---|
| 通义听悟 | 有，**最多 4 层** | 短句式论断（名词短语+谓词/限定，可独立成立） | 官方文档，有示例 |
| Notta | 有 | 笔记正文要点句（由 heading 级别 + 缩进投影而来） | 官方帮助文档，有 7 级映射表 |
| 讯飞听见 | 有 | **未披露**（只说"语义聚类+上下文关联度"） | 官方发布文，不含叶子形态 |
| 飞书妙记 | **没有导图** | —— | 官方 API 字段清单里无导图字段 |
| Otter.ai | Outline（不是导图） | "top points"（要点句），关键词是**另一个独立产物** | 官方帮助文档 |
| AI好记 aihaoji | 有，多级 | "课程主题→章节→知识点"三级，且会截 PPT/公式画面 | 官方博客，举例但不含算法 |
| tl;dv | 有章节/摘要 | **没查到**官方对叶子形态的定义 | —— |

### 1.2 通义听悟（最值得抄的一个）

来源：<https://help.aliyun.com/zh/tingwu/large-model-summary.md>

原文：

> 思维导图：根据音视频内容进行总结，并生成绘制思维导图所需的数据结构……**目前思维导图最多生成四个层级（树结构最大深度为四层）**。

数据结构是 `MindMapSummary[]`，每项 `{ Title: string, Topic: 子节点列表 }`——就是递归的 Title/Topic 树。

官方示例输出里的叶子长这样（可直接对照，这就是"好叶子"的样子）：

- 「总部位于杭州，分设在全球多个地点（美国、以色列、新加坡等）」
- 「强噪声、多人交谈、多种电器干扰」
- 「语意理解：同音异义词的情感区分」
- 「Call Center 自动化应答」
- 「AI 参与会议，提高决策质量」

三个可直接抄的形态特征：

1. **每个叶子都能脱离上下文独立读懂**——有主语、有谓语或限定语。
2. **并列同类项被聚合到同一个父节点下**，不平铺（三个挑战挂在一个"挑战"节点下）。
3. **层级封顶**（4 层）。这是防树爆炸的工程约束，不是能力上限。

### 1.3 Notta（"导图 = 笔记的视图"的范式）

来源：<https://support.notta.ai/hc/en-us/articles/37337632678555-Generate-mind-maps-from-AI-Notes>

官方给了 7 级映射表：

| 导图层 | 来源 |
|---|---|
| Level 1 Subject（Main Theme） | 录音标题 |
| Level 2 | 主标题（Heading 1，0 级缩进） |
| Level 3 | 子标题，或主标题后的正文 |
| Level 4 | 更小标题（Heading 3），或正文 |
| Level 5 | 普通正文 |
| Level 6 | 1 级缩进正文 |
| Level 7 | 2 级缩进正文 |

**关键机制：导图不独立生成，完全由 AI Notes 的 heading 级别 + 缩进推导。** 想改导图就去改 Summary 文本。

这条对我们的意义：**导图不该是"另一套抽取算法"，而该是笔记结构的投影。** 现在的问题是笔记里的要点本身被截断了（见 §4.6 实测），投影出来自然是空壳。

配套事实（<https://support.notta.ai/hc/en-us/articles/15451756393243-Generate-AI-Notes-with-templates>）：AI Notes 由模板驱动（如 CHAMP 模板）；**最少 200 字符才生成**；音频 <90 分钟时会给章节/待办打时间戳。

### 1.4 讯飞听见

来源：<https://www.iflyrec.com/zhuanxie/67ff0ca6.html>（2025-04-16 官方发布文）

原文：

> 录音结束后，系统通过算法对**文本进行语义聚类分析，结合上下文关联度**生成**层级分明**的思维导图，用户可对导图进行**重新生成**直至满意。

产品矩阵是「笔记 / AI纪要 / 思维导图 / AI对话」四件套，明确主打「会议记录、课程学习、访谈整理」。

**没有披露叶子内容形态。** 我不编。但"可重新生成直至满意"这个交互值得抄——承认自动生成不可靠，把重试做成产品功能。

### 1.5 飞书妙记（反例，很重要）

来源：<https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/minutes-v1/minute/artifacts.md>

妙记的 AI 产物字段只有：`summary`、`minute_chapters[]`（title / start_ms / stop_ms / summary_content）、`minute_todos[]`、`keywords[]`、`transcript`。**没有导图字段。**

官方对章节的定义：

> title：章节标题，用于区分纪要内不同的讨论模块，需简洁明确概括章节核心内容。
> summary_content：章节的核心讨论内容摘要，需准确提炼该章节的决策结果、行动项、待跟进事项等关键信息。支持富文本格式，最大长度限制为 10000 字符。

示例 summary_content 是「1. …；2. …；3. 风险预警：…」这种编号要点句。

**结论：飞书妙记不自动生成思维导图。** 网上"妙记能生成导图"的说法，多半把「思维笔记」（手动大纲转导图）当成了妙记功能。这是个现成的降级方案参照：**如果导图不可靠，退一步给「章节 + 编号要点」更稳**。

### 1.6 Otter.ai（把关键词和结构分开，正好治我们的病）

来源：<https://help.otter.ai/hc/en-us/articles/5093228433687-Conversation-Page-Overview>

三件套：

- **Summary**：短 AI 摘要
- **Action Items**：AI 自动识别并自动指派给相关人，可点 "View in transcript" 回溯原句
- **Outline**：原文 "Outline of the **top points** of your conversation"

关键词在 Transcript 标签下**单独一块**，而且**不可编辑**。

来源 <https://help.otter.ai/hc/en-us/articles/9156381229079-Meeting-Summary-Overview>：摘要邮件含 Automated Summary / Action Items / Highlights（来自 outline）/ Automated Slides；**≤500 词的对话不生成摘要**。

**启示直击要害：Otter 把「关键词」和「结构大纲」当成两个完全不同的产物。我们现在犯的错，是把关键词当成了结构。** 关键词可以有，但它该待在另一个位置（比如主题下面的一行 tag），不该当叶子。

### 1.7 AI好记（唯一明确面向"课程"的）

来源：<https://aihaoji.com/blog/ai-video-note>

导图结构官方举例：「计算机网络基础 → 网络模型 → TCP/IP → 数据传输 → 常见协议」，描述为"按照课程主题、章节和知识点展示多级学习结构"。

最值得注意的一条——它自己承认纯转写的天花板：

> 如果只有逐字稿，可能只能看到"这里代入公式""接下来进行化简"之类的描述

所以它的做法是**自动识别并截取视频里的 PPT 页面/图表/公式画面**，与讲解文字配对成图文笔记。

其他能力：专业术语识别错误可手工纠错；导图节点可点击定位回原文/视频时间戳；可导出 XMind；支持自定义 Prompt（如学术讲座按"研究背景—研究方法—主要结果—结论"）。

**未公开叶子生成算法细节。**

## 2. 教育测量学视角：一节课的"知识点"怎么分类

### 2.1 布卢姆修订版：两维，正好能当标签体系

来源：Britannica <https://www.britannica.com/topic/Blooms-taxonomy>

2001 年修订（Anderson & Krathwohl）把布卢姆改成**两维**：

- **知识维（knowledge dimension）**：factual（事实性）/ conceptual（概念性）/ procedural（程序性）/ metacognitive（元认知）
- **认知维（cognitive dimension）**：remembering / understanding / applying / analyzing / evaluating / creating

中文六层原文（广东石油化工学院 <https://jsjxfzzx.gdupt.edu.cn/info/1148/1606.htm>）：

> 认知领域教育目标由最简单到最复杂的六个层次，依序为**记忆、理解、应用、分析、评价和创造**。
> 应用：是指对所学习的概念、法则、原理的运用。它要求在没有说明问题解决模式的情况下，学会正确地把抽象概念运用于适当的情况。

荷兰 SLO 对四类知识给了具体例子（<https://www.slo.nl/thema/meer/vaardigheden-landelijke-curriculum/vaardigheden-kennis-vaak-samen/vier-belangrijke-soorten-kennis/>）：**事实性知识**的例子包括拼写规则、乘法表、勾股定理、历史年代、地名、动植物名称、化学结构式；**概念性知识**是概念含义（数、词、分数、函数、时代、比例、力、反应、生物体、民主）以及概念间关系的连贯整体；**程序性知识**是完成任务/解决问题的程序，可熟练化为 routine；**元认知知识**是关于自身知识与学习方式的知识。

**工程落地的取舍**：知识维直接可用，认知维太难判（"理解"还是"应用"从一句话里看不出来）。
所以**标签 = 知识维 + 学科子类型**，不碰认知维。

### 2.2 中国教学大纲里的分类（比布卢姆更贴地气，直接可用）

这是本次调研最有用的发现。中国高校教学大纲对知识点有一套**成文的、可照抄的**分类。

**（1）两组知识点 + 三档掌握动词**

来源：西安培华学院《关于修（制）定课程教学大纲的意见》<https://www.peihua.edu.cn/jwglzx/info/1040/2149.htm>

原文：

> 有关**定义、定理、性质、特征**等概念可按"**知道、了解、理解**"三个层次要求；有关**计算、解法、公式、法则**等方法的内容，可按"**学习、掌握、熟练掌握**"三个层次要求；对于技能、操作可按"观察、学会、掌握、应用"等几个层次要求。同时，要注明不同教学层次所对应的考核要求。

同一份文件规定每章固定六个板块：基本目的与要求（基本概念、理论、原理）/ 教学的重点和难点 / 教学主要内容 / 作业习题或思考讨论题 / 实践教学安排 / 教学方法与手段。

→ **这直接证明：在中国教学语境里，"公式""定理""定义""法则"就是并列的独立知识点类别，不是同一个东西的不同说法。**

**（2）高等数学大纲的实际写法**（兰州工业学院，97 页 PDF，<https://jcb.lzit.edu.cn/__local/9/F2/68/D94F93A113036F2BE891555A748_60632E53_1112A5.pdf>）

每章固定三段：**教学内容 → 教学要求（"理解/掌握/了解 + 名词"）→ 教学重点与难点**。

「函数与极限」章教学重点原文：

> 函数的概念；复合函数的概念；基本初等函数的性质及图形；极限的概念；极限的运算法则；两个重要极限；求极限的基本方法；无穷小的概念；无穷小的比较；函数连续性和间断点的概念。

「微分中值定理与导数的应用」章原文：

> （1）微分中值定理：罗尔定理；拉格朗日中值定理；柯西中值定理；三个定理之间的关系。

→ 注意这条大纲的**重点条目全是"概念 + 法则/方法/定理"的混合体**，且每条都能独立读懂。这就是好叶子的模板。

**（3）医学大纲**（重庆医科大学《系统解剖学教学大纲》<https://basiclab.cqmu.edu.cn/__local/7/36/3F/2B522FDA7BF1D3C836A3217BF63_6AD48523_2997C.pdf>）

原文：

> 在每章的"目的要求"项中规定了**掌握、熟悉与了解的三级要求**，并在"教学内容"项中分别注明教学重点、难点以及教学方法。

每章四段式：目的要求 / 主要内容和教学方法 / 教学重点和难点 / 思考题；条目形如"掌握椎骨的一般形态和各部椎骨的主要特征""熟悉骨性胸廓的组成、形态和功能"。

**（4）工科大纲**（东莞理工学院《工程制图（1）》<https://jxx.dgut.edu.cn/__local/B/6D/62/EE1F59305EEEAEC0F8FA0D07340_E43521EC_2CABA.pdf>）

"理论教学进程表"逐周给：教学主题 / **教学的重点与难点** / 教学方式 / 作业安排。原文行：

> 点、直线的投影 — 重点：点、直线的投影规律及表示　难点：投影与空间的关系
> 组合体的尺寸标注 — 重点：尺寸注法　难点：有关规定、常见注法
> 机件的视图、剖视图 — 重点：各种视图的表达方式、剖视的概念　难点：剖视的理解

**→ 工科的"重点/难点"本身就该是叶子候选。**

### 2.3 值得抄的一张分类表

把上面几套合起来，落到"叶子类型标签"：

| 上位（布卢姆知识维） | 类型标签 | 触发特征（可规则化） |
|---|---|---|
| 概念性 | **定义** | `称为 / 叫做 / 指的是 / 定义为 / 是指 / 记作` |
| 概念性 | **定理** | `定理 / 定律 / 法则 / 推论 / 引理 / 性质 / 判别式` |
| 事实性 | **公式** | `= / 等于 / 平方 / 次方 / 根号 / sin / cos / ln / 积分 / 求导` |
| 程序性 | **步骤** | `第一步 / 首先 / 然后 / 接着 / 最后`，或笔记里的编号列表 |
| 程序性 | **例题** | `例X / 第X题 / 这道题 / 求解` |
| 概念性 | **结论** | `所以 / 因此 / 故 / 可见 / 综上 / 总之` |
| 元认知 | **易错** | `注意 / 记住 / 千万别 / 容易错 / 关键` |

这套标签和本机 `public/mindmap.js` 里现有的 `LEAF_TYPES`（formula / define / theorem / result / step / example / pitfall）**几乎一一对应**——方向是对的，问题出在闸门把它杀光了（§4.6）。

依据是 §2.2 的各科大纲原文 + 各科课程标准的核心素养。

### 3.1 数学 / 物理：**公式、定理、推导步骤、例题**

## 4. 工程可行的抽取方法（纯规则 / 统计能做到什么程度）

### 4.1 公式：能抓，但必须"符号层"和"读法层"分开做

**核心资产：官方给的中文读法对照表。**

来源：讯飞开放平台《Latex能力支持说明》<https://www.xfyun.cn/doc/spark/tts_latex.html>

适用范围原文："发音人：仅 x6 系列发音人支持；语种：中文；**适用场景：中小学数学场景**"。

这张表本来是"LaTeX → 中文读法"，**反过来就是"中文口语 → LaTeX"的规则表**。摘录：

| LaTeX | 中文读法 |
|---|---|
| `\frac{2}{3}` | 三分之二 |
| `\sqrt{9}=3` | 根号下九等于三 |
| `\sqrt[3]{8}=2` | 三次根号下八等于二 |
| `2^{1}` | 二的一次方 |
| `\log_{a}{b}` | 以 a 为底的 b 的对数 |
| `\sin 30^\circ` | sine 三十度 |
| `\pi` | 派 |
| `A\parallel B` | A 平行于 B |
| `AB \perp BC` | AB 垂直于 BC |
| `\because...\therefore...` | 因为…所以… |

**官方明确列出的"不支持"项，正好就是纯规则的边界**（重要，别硬做）：坐标系、`①②` 这类圈号、向量 `\overrightarrow{AP}\cdot\boldsymbol{u}`、交并集 `[-3,1)\cup(1,+\infty)`、包含关系 `A\subseteq B`、导数撇号区分 `A'B'C'`、区间、矩阵 `\mathbf{A}`、求和 `\sum_{i=1}^{n} i`、极限 `\lim`。

**必做的一步：同音错映射表。** MathSpeech 的示例就是 sin→"side"。中文课堂里高频的固定错误可枚举：

```
sine/cos/ln/log  ←  赛因/扣赛因/洛因/落个
派 ← 派/π/盼
谬 ← μ/缪/谬
德塔 ← Δ/delta
西格玛 ← Σ/sigma
兰姆达 ← λ
伊普西龙 ← ε
根号 ← 根号/更好/跟号
```

**分层设计（这一步很关键）**：

- **L1 符号层**：句子里有 `= / ² / √ / ³ / ∂ / ∫` 这类真符号，或 `X 的 N 次方`。**直接标 [公式]，原样呈现**。本机能做到。
- **L2 读法层**：全是中文读法（"根号下 A 的平方减 X 的平方"）。做**保守映射**，只映射对照表里有的形态，映射失败就原样呈现，不猜。
- **L3 语义层**（"这个式子两边求导"）：**不要做**。这是模型活。

### 4.2 定义：**触发词这条路在真实课堂里基本是死的**

本机实测（§4.6）：`什么叫/什么是/啥叫/何谓` 在高数 A 课 1017 句里只命中 **1 句（0.1%）**，高数 B 课 **0 句（0%）**。`称为/叫做/指的是/定义为` 也只有 0.1%–0.7%。

原因很实在：老师上课不说"什么叫导数"，老师说"导数呢，就是……"或者干脆直接用。

**替代方案（可行）**：不要等触发词，改成**「术语 + 上下文句」**：

1. 先用学科词尾表（现有 `LBL_TERM_TAIL` 就有 约 100 个）在句子里找术语；
2. 取该术语**首次出现**的那句，把术语当前缀、句子压成说明；
3. 输出 `导数：函数在某点的瞬时变化率` 这种形态。

这就是现有笔记里"名词短语：说明"结构的来源，形态是对的——**问题在闸门把带字母/符号的那些全杀了**（§4.6）。

### 4.3 结论 / 定理：连接词是最稳的信号

来源：《面向意图性的篇章话题结构分析研究与展望》奚雪峰等，《计算机学报》42(12), 2019，<http://cjc.ict.ac.cn/online/onlinepaper/xxf-2019121090823.pdf>

原文两条关键事实：

> 显式篇章和隐式篇章关系的数量基本上属于**各占半壁江山**，但显式篇章关系所包含的歧义不多，大约仅占 **2%**，而且存在确定的连接词，因此相对较为容易识别。
> 对隐式篇章关系识别的效果决定了整个篇章结构关系分析的成败。

**工程含义**：靠显式连接词能覆盖约一半，**且这半几乎无歧义**；剩下一半（隐式）不要硬做。

规则表：

```
结论：所以 / 因此 / 故 / 于是 / 由此可见 / 综上 / 总之 / 也就是说 / 换句话说 / 结论是
定理：定理 / 定律 / 法则 / 推论 / 引理 / 性质 / 判别式 / 充要 / 必要 / 充分
强调：记住 / 记牢 / 注意 / 千万别 / 一定 / 必须 / 关键 / 考点 / 必考 / 易错
```

本机命中率：结论类 1.3%–4.9%，强调类 0.3%–2.2%。**够用**——一节课 5 个主题，每主题捞 1–2 条结论是合理的密度。

⚠️ **「所以」有个坑**：它常出现在"所以我们现在来看…"这种过渡句里，不是结论。必须配一条"去掉连接词后还剩什么"的检查——现有 `EMPTY_LEAF` 干的就是这件事。

### 4.4 例题 / 步骤

```
例题：例[一二三…0-9] / 第X题 / 第X道题 / 例题 / 这道题 / 这个题 / 练习题 / 习题
步骤：第一步 / 第二步 / 首先 / 其次 / 然后 / 接着 / 最后
```

本机命中率：例题 0–2.9%，步骤 4.6%–7.6%。

**步骤类有个隐藏富矿**：LLM 生成的笔记里，步骤是**缩进编号列表**，不是口语句。

```markdown
- 操作步骤：
  1. 对 F(x,y)=0 两边求导，右端得 0
  2. 左端按复合函数求导
  3. 解出 dy/dx
```

**这三条子项在现在的代码里被直接丢掉了**（`outlineFromMarkdown` 只认 `^-\s+`，见 §4.6 实测）。捞回来，不需要任何 NLP。

### 4.5 中文关键短语抽取：公开实测说了什么

来源：**Unsupervised Derivation of Keyword Summary for Short Texts**，ACM TOIT 21(2) Article 45, 2021，DOI 10.1145/3397162，<https://dlnext.acm.org/doi/fullHtml/10.1145/3397162>

三个数据集：RA-MDS（英文新闻评论，平均 71 词）、**China Telecom（中文客服反馈，24 主题 / 2256 条 / 平均 14 词）**、CTD（临床，平均 26 词）。指标 ROUGE-L。

**中文短文本上的 F1（表 2）**：

| 方法 | F1 |
|---|---|
| FCWRank（论文方法） | **56.5** |
| Sequence-Freq | 49.1 |
| Wordset-Freq | 47.7 |
| LDA-BTM | 41.4 |
| LDA-WNTM | 35.1 |
| **TextRank** | **29.8** |

**TextRank 精确率在三个数据集上全部垫底**：RA-MDS 29.6 / China Telecom **26.0** / CTD 26.4。

原文批评：

> both statistical methods (e.g., **TF-IDF**) and graph-based methods (e.g., **TextRank**) can neither capture co-occurrences in different documents nor convey semantics as compared to topic models, hence the highly ranked keywords may not make sense with the topic of the short texts.

长度敏感性：ROUGE-L F1/recall 最优在 **20–29 词**，precision 最优在 **30–39 词**；更短"fewer keywords"，更长"more noisy words"。

**→ 一节课的一条要点通常 10–40 字，正好落在 TextRank 最差的区间。这解释了为什么现在的叶子全是碎片，且不是调参能救的。**

可借鉴的方法要点：FP-growth 挖**频繁闭合词集**当候选 → 异构网络（词集↔文档 inclusion 边、词集↔词集 cosine 边）→ TextRank 与 HITS 交替迭代 → 最后按语料内相对位置做 Keywords Ordering。中文预处理用 **HanLP** 分词 + 同义词替换 + 领域词典过滤。

**中文短文本的公开实测只有这一个可用数字。** 其余的（SemEval2017、Inspec）都是英文，不能直接搬。

**实验 3：定位到具体是哪一行杀掉的**

`public/mindmap.js:62`：

```js
const LONE_LATIN = /[\u4e00-\u9fff][A-Za-z](?![A-Za-z])|(?<![A-Za-z])[A-Za-z][\u4e00-\u9fff]/;
```

本意是挡 ASR 残渣（`R定义这个S`），但它同时挡掉了：

| `适用于幂指函数（如y=x^(sin x)）` | ✅ 杀 | `如y` |
| `操作步骤：对F(x,y)=0两边求导` | 放行（因为压缩后那段没字母） | — |

**这就是"公式永远出不来"的直接原因之一**——所有真正带公式的句子，都因为"汉字紧贴一个字母"被当成 ASR 残渣扔了。**而 `y=f(x)` 里的 `y` 根本不是残渣，是数学表达式。**

同类问题还有三处：

- `public/note.js:335`：`goodSeg` 里 `/[0-9A-Za-z]/` 一律拒绝。注释原文写"带数字、字母的是习题号/章节号/公式（`课后习题 6.3` `时间复杂度是 O`），不是概念"——**判断没错，但结论反了：公式恰恰是我们要的。**
- `public/note.js:404`：`acceptable` 里 `/^(?:第|其|该|此|每|各|另|前|后)/` 开头一律拒绝 → **"第一步/第二步/第三步"被直接杀掉**，步骤类叶子全军覆没。
- `public/note.js:128` `outlineFromMarkdown`：只认 `^-\s+`，**` 1. ` 这种缩进编号子项被丢弃** → 高数笔记里"操作步骤"下面那三条编号步骤全丢了（实测：`"操作步骤："` 只剩一个带冒号的空壳）。

**实验 4：只改一处，覆盖率变化**

松开 `LONE_LATIN`（当句子里有真数学符号时放行）+ 收编编号子项：

| 课 | 要点 | 现状叶子 | 改后叶子 | 现状覆盖 | 改后覆盖 |
|---|---|---|---|---|---|
| 高数B | 10 | 4 | **9** | 40% | **90%** |
| 高数A | 56 | 5 | **14** | 9% | **25%** |
| 思政 | 15 | 13 | 13 | 87% | 87% |
| 工程制图 | 13 | 11 | 12 | 85% | **92%** |

高数 B 改后实际产出：

```
[公式] 显函数：能明确表示为y=f
[定义] 隐函数：只能表示为F(x
[要点] 引入隐函数的意义：处理无法解析显化的方程
[公式] 核心思想：将y视为x的函数y=f(x)
[步骤] 操作步骤
[公式] 关键点：即使无法显式表示y=f(x)
[公式] 3√3/2)处的切线求法
[要点] 二阶导求法：一阶导结果再次求导
[公式] 适用于幂指函数（如y=x^(sin x)）
```

**注意：这只是"能出东西了"，不是"好了"。** 还有两个明显缺陷：①`y=f` 被 24 字上限截断；②`[步骤] 操作步骤` 还是空壳（编号子项没接上，因为压缩时取了冒号前的名词短语）。

## 5. 三个可落地的方案

按「改动量 / 预期效果」排序。三个方案可以叠加，不互斥。

### 方案 A：松闸 + 收编号（1 天，改动最小的止血）

**做什么**

1. `LONE_LATIN` 改成条件放行：句子里有真数学符号（`= ² √ ∫ ∂` 或 `X的N次方` 或 `f(x)` 形态）时不判残渣。
2. `acceptable` 放开 `第X步`；`goodSeg` 对含数字/字母但**同时含数学符号**的片段放行。
3. `outlineFromMarkdown` 收编 ` 1. ` / ` 2. ` 缩进编号子项，拼成 `名词：步骤1；步骤2；步骤3`。
4. 叶子长度上限从 24 提到 32（`y=f(x)` 这类表达式需要位数）。
5. 主题下按 `TYPE_RANK` 排序**已经实现了**——保留。

**对高数课的产出**：约等于 §4.6 实验 4 的表——高数 B 从 4 条 → 9 条，覆盖 40% → 90%；高数 A 从 5 条 → 14 条。

**预期效果**：用户最直观的感受是"公式终于出来了"。但会出现"名词：半截公式"这种不完整的叶子。

**难度**：低。纯本地改，不依赖模型。

---

### 方案 B：类型槽位 + 分学科规则包（3–5 天，推荐主路径）

**做什么**

1. **固定槽位，不再"抽无限多叶子"**。每个主题最多出 5 条，槽位固定：

   ```
   公式 / 定理 / 结论 / 步骤 / 例题 / 易错 / 定义
   ```

   每个类型最多 2 条，按 §3 的学科优先级排序。**一节课 5 个主题 × 4 条 ≈ 20 个叶子，正好是"看一遍能记住"的密度。**

2. **分学科规则包**（§3.6 那张表），用课名/标题里的关键词判定：
   - `高数|数学|物理|线代|概率` → 数学包（公式优先）
   - `制图|电路|机械|工程` → 工科包（规范/步骤优先）
   - `思政|历史|马原|毛概` → 文科包（观点/人物优先，**禁用"强调"规则**——实测会捞到"期中考试八十分，不满意"）
   - `解剖|生理|病理|生物` → 医学包（结构/功能优先）
   - `英语|语文|HSK|汉语` → 语言包（语法点+例句）
   - 判不出来 → 通用包（结论 > 步骤 > 定义）

3. **公式分层**（§4.1）：L1 符号层照原样、L2 读法层只做对照表映射、L3 不做。

4. **兜底不要"摘半句"**。现在 `app.js:755` 抽不出就 `squeezeLabel(p.text, 10)`——这恰恰是产残渣的路径。改成：抽不出就**这一节只显示主题**，或者显示"这段是例题讲解，没有可提炼的结论"。

**对高数课的产出**（预期）：

```
隐函数与显函数的定义与区别
  [公式] 显函数：能表示为 y=f(x)
  [定义] 隐函数：F(x,y)=0，无法显式解出 y
  [要点] 引入隐函数的意义：处理无法解析显化的方程

隐函数求导的基本原理
  [公式] 对 F(x,y)=0 两边关于 x 求导
  [步骤] ①两边求导得 ∂F/∂x + (∂F/∂y)·dy/dx = 0
       ②解出 dy/dx
  [易错] y 必须当作 x 的函数处理

隐函数求导的应用：椭圆切线问题
  [例题] 椭圆 x²/16 + y²/9 = 1 在点 (2, 3√3/2) 的切线
  [公式] 求得 y' = -9x/(16y)，代入得 k = -√3/4
```

**预期效果**：这是"用户打开就想截图发朋友圈"的形态。每一行都独立可读、带类型、能对回原文时间戳。

**难度**：中。规则包要写 5 套；槽位要改渲染。

---

### 方案 C：让笔记先写对，导图只做投影（1–2 周，治本）

**做什么**

照 Notta 的范式：**导图不独立生成，是笔记结构的投影**。

1. **让 LLM 生成的笔记就用"类型前缀 + 完整句子"写**。现在的 markdown 已经是 `- 核心思想：…` 这个形态，方向对——只要提示词里硬性要求：
   > 每条要点必须以「类型词：完整命题」开头，类型词只能取：公式 / 定义 / 定理 / 结论 / 步骤 / 例题 / 易错 / 补充。
   > 公式必须写成 `y=f(x)` 形态，不许写成"y 等于 f x"。

2. **LLM 输出后加一步自检**（STRUCTSUM 的结论：critique+重写能 +37pp）：把要点连同原文片段回灌，判 `accurate / vague / inaccurate / duplicate`，不通过的重写。这正是华为云那篇工程文用的办法（<https://bbs.huaweicloud.com/blogs/484000>，原文承认"直接用一个巨大的 Prompt 做所有事情效果不好——LLM 在多任务混合 Prompt 下容易'偷懒'"）。

3. **导图 = outline 的一层投影**，`outlineFromMarkdown` 只负责解析，不负责"再想一遍"。

4. **保留人工编辑**：LDK 2025 的 F1 天花板 0.26–0.29 说明全自动不可能完美，必须能改。改 markdown 就等于改导图（Notta 就是这么设计的）。

**对高数课的产出**：直接就是 §5 方案 B 里那张图，且能到"教科书级"——因为写笔记的模型已经知道公式是什么了，规则层不用猜。

**预期效果**：上限最高。但要动提示词 + 加自检回路，且**离线模式下没有 LLM，只能靠方案 A/B 兜**。

**难度**：高（要改 summarize/llm 那条链路，还要处理离线/在线两种模式）。

## 6. 推荐方案

**先做方案 A（1 天），再上方案 B（3–5 天），方案 C 排在下一版。**

理由，按优先级：

1. **A 是止血，且证据最硬。** 本机实测已经证明：光松开 `LONE_LATIN` 一个闸门 + 收编编号子项，高数 B 的叶子覆盖率就从 40% 到 90%。用户抱怨"公式出不来"，这一条直接命中。而且它不改架构，风险最低。

2. **B 才是"改生成逻辑"的正解。** 产品负责人的原话是"最重要的是什么，公式，结论，换成其他科的重点是什么"——这句话本身就是方案 B 的需求书：**类型 + 分学科**。而且它有三重支撑：中国教学大纲成文的分类（定义/定理/性质/特征 vs 计算/解法/公式/法则）、布卢姆知识维、以及本机实测"工程制图公式规则 0 命中"这个反面证据。

3. **B 里最该先做的一件事：把兜底从"摘半句"改成"宁缺勿滥"。** 现在 `squeezeLabel(p.text, 10)` 这条兜底路径，就是"看一""道题""阶档"这些残渣的生产线。用户说"实在不会不要瞎编"——**空着比挂残渣好**，这条产品判断应该写进代码。

4. **C 治本但不能救急。** Notta 的范式是对的（导图只是笔记的视图），但离线模式没有 LLM，必须靠 A/B 兜底。而且 C 依赖提示词质量和自检回路，不是一天能验证的。

5. **不要做的事**（有明确证据）：
   - **不要在 TextRank/词图上调参。** 短文本上它精确率 26.0，是三档里最低的；论文原话就是"抽出的关键词可能和短文本主题没关系"。
   - **不要等"什么叫/定义为"触发词抽定义。** 真实高数课命中率 0–0.1%。
   - **不要试图用规则还原句中公式的完整语义。** ICLR 2026 的实测：句中公式 CER 39.68，SOTA 模型也只能到 27.21（孤立公式）。规则层只做高频读法映射。
   - **不要给"强调"规则放行所有含"考试/分数"的句子。** 实测在思政课上捞到的是"期中考试八十分，不满意"。

**一句话**：叶子不该是词，也不该是原文句子，而该是**「类型标签 + 一句能独立读懂的命题」**；类型由学科决定，命题由笔记负责写对，导图只做投影。
