# 底层数据流诊断

> 用体检脚本 `tests/audit-data-integrity.mjs` + 四个探针对 7 条真实录音跑出来的结论。
> 目的：不是修某一条录音，而是找出「换个录音进来照样有问题」的结构性病因。

## 一、结论：四个结构性缺口

### 缺口 1：同一份文字有两套切句实现，且互相不兼容

| 实现 | 位置 | 用途 | 中文句末符 |
|---|---|---|---|
| A 朴素正则 | `server.mjs:397-415` | 转写落盘时切 `segments` | `。！？；!?;…` |
| B 状态机 | `public/summarize.js:71-116` | 生成笔记时切 `sentences` | `。！？!?；;…` + 英文句点规则 + 换行 + `splitLong(80)` |

同一条录音实测：`62b4f73d` A 切出 **2247 块**，B 切出 **2095 句**；`1305e386` A 切 **21 块**、B 切 **142 句**（差 6.8 倍）。逐字稿里看到的一行，和笔记里对应的时间戳不是同一句。

### 缺口 2：B 切法会静默丢内容，逐字稿丢的是真字

`splitSentences` 末尾：

```js
return out.filter((s) => s.replace(/[^\u4e00-\u9fffA-Za-z0-9]/g, '').length >= 2);
```

把「只含 1 个有效字符」的句子整句丢掉。实测 `62b4f73d` 丢掉 **157 块 / 314 字**，全是 `"嗯。"`、`"啊。"`、`"对。"`、`"是。"`、`"好。"` 这类单字语气词。

- 对**生成笔记**：丢掉是对的（这些不是要点）。
- 对**逐字稿**：丢掉是错的——用户搜「嗯」搜不到，SRT 导出少内容。

问题在于**同一个函数被两种用途共用，没有区分「要保真」还是「要提纯」**。

### 缺口 3：笔记没有版本戳，算法升级后旧笔记永远不会自动更新

`meta.json` 只有 `["id","title","course","createdAt","updatedAt","audioFile","originalName","mime","size","duration","status","engine"]`——**没有任何算法版本字段**。`note.json` 里只有 `generator: 'offline'`，也没有版本号。

后果：`2d1953e1`（55 个主题）、`62b4f73d`（391 个主题）是旧 `segmentTopics`（每 5 句一刀）的产物，标题全是碎片拼接。当前算法对同样数据给出 **7 个 / 9 个**合理主题，但系统**不知道旧笔记过期了**，打开还是旧的。

`62b4f73d` 的 391 个主题里 **388 个是碎片**；`1305e386` **24/24**；`2d1953e1` **55/55**。三条全部命中，不是个例。

### 缺口 4：转写落盘时不校验，什么形状都存

`server.mjs:397-415` 只在 `(!segments.length || !hasRealTimestamps) && text` 时兜底切段。反过来，如果服务商回了 segments 但里面有超长段、或时间轴非单调、或相邻段重叠，**一律原样落盘**。

实测 `2d1953e1` 有 1 处相邻段重叠，`defe45a2`/`0e0eafc7` 的 13 段平均每段 53 秒（远超正常语句长度）——这些都被原样存下了。

## 二、不是缺口的部分（已验证澄清）

- **时间轴没有漂移**：`toSentences()` 在 segments 有真时间戳时**原样沿用**（实测 `62b4f73d` 2095 段→2095 句，段首起点不符 0 处，首尾差 0.0s）。之前看到的 473 秒偏差是我喂纯文本产生的假象——纯文本走 4.2 字/秒估算，真实 segments 不走。
- **全文字段与分段内容一致**：`text` 与 `segments[].text` 拼接的差值仅来自 B 切法的 filter，不是存储层丢字。
- **笔记的 keywords/definitions/cueGroups/questions/globalKeyPoints 在重生成后逐条不变**（`62b4f73d` 重生成实测：20/20、6/6、5/5、13/13、8/8 全等），说明这些提取器是稳定的，变的只有 `outline` 分段粒度。

## 三、修复方向

| 缺口 | 修法 | 影响面 |
|---|---|---|
| 1 两套切句 | 让 `server.mjs` 复用 `public/summarize.js` 的 `splitSentences`（服务端已有 import 先例：`providers.js`、`llm.js`） | 新转写的落盘格式统一 |
| 2 静默丢字 | 给 `splitSentences` 加 `keepShort` 选项；逐字稿路径用 `keepShort:true`，笔记路径用默认 | 逐字稿保真，笔记保持干净 |
| 3 无版本戳 | `note.json` 写入时记录 `algoVersion`；读取时版本落后就标记「可升级」并在界面给出提示/一键重生成 | 旧笔记可被发现和修复 |
| 4 落盘不校验 | `writeDoc('transcript')` 前跑一遍 `normalizeTranscript`：修时间轴、切超长段、去重叠 | 任何来源的脏数据都自愈 |

优先级：**4 > 1 > 2 > 3**。缺口 4 是「什么录音进来都自愈」的关键；缺口 1、2 是根因；缺口 3 让存量数据可管理。
